Mental Model

A MuJoCo model starts as an MJCF file (XML). The parser reads it and builds a tree of bodies. Each body lives in a parent body's coordinate frame. The root is always worldbody.

Bodies by themselves are invisible and massless. You give them shape with geoms (geometry: spheres, capsules, boxes, meshes). You give them motion with joints. A joint lives between a body and its parent, defining how they can move relative to each other.

Think of it like a skeleton: bodies are the bones, joints are the articulations between bones, and geoms are the flesh that gives bones their physical shape and collision surface.

MJCF Source
pendulum.xml 
<mujoco model="pendulum">
  <worldbody>
    <!-- The pivot mount, fixed in world -->
    <body name="pivot" pos="0 0 0.5">
      <geom type="sphere" size="0.02" />

      <!-- Joint goes between parent (world) and this body -->
      <joint type="hinge" axis="0 1 0" />

      <!-- Rod: capsule centered at half the rod length below -->
      <geom type="capsule" fromto="0 0 0  0 0 -0.4"
            size="0.01" />

      <!-- Bob at the end of the rod -->
      <body name="bob" pos="0 0 -0.4">
        <geom type="sphere" size="0.05"
              rgba="1 0.42 0.21 1" />
      </body>
    </body>
  </worldbody>
</mujoco>

Mental Model

Every body in MuJoCo carries its own local coordinate frame. When you write pos="0 0 -0.4" on a child body, that offset is measured in the parent's frame, not the world frame.

To find where something is in the world, MuJoCo chains transforms from the root: world to body A, body A to body B, and so on. This is the forward kinematics pass. After mj_forward runs, every body's world position is stored in data.xpos.

When a joint rotates, only the local frame of that body (and its children) rotates with it. The parent stays fixed. This is why a hinge on the pendulum pivot rotates the entire rod and bob together: they are children of that pivot body.

Python Source
frame_check.py 
import mujoco

model = mujoco.MjModel.from_xml_path("two_link.xml")
data  = mujoco.MjData(model)

# Set the hinge angle (in radians)
data.qpos[0] = 0.5

# Run forward kinematics to compute world positions
mujoco.mj_forward(model, data)

# data.xpos holds world positions of every body
base_world  = data.xpos[1]  # body 1: base
child_world = data.xpos[2]  # body 2: child

print(f"base  world pos: {base_world}")
print(f"child world pos: {child_world}")

After a 90-degree Y rotation, the local z-axis points along the world x-axis. The child offset [0, 0, 0.3] in local becomes [0.3, 0, 0] in the base frame. The child world position is [0.3, 0, 0.4]. It moved sideways instead of upward.

Mental Model

MuJoCo separates state from derived quantities. The state is qpos (joint positions) and qvel (joint velocities). Everything else, including world positions, forces, and accelerations, is computed from the state.

mj_forward(model, data) computes all derived quantities from the current state without advancing time. You call it after manually setting qpos/qvel to see where things end up.

mj_step(model, data) integrates the equations of motion and advances the simulation by one timestep. It updates qpos and qvel based on forces, gravity, contacts, and actuators. After stepping, data.time advances by model.opt.timestep.

Key insight: forward = "given this state, compute everything." step = "compute everything, then evolve the state by one dt."

Python Source
step_vs_forward.py 
import mujoco
import numpy as np

model = mujoco.MjModel.from_xml_path("pendulum.xml")
data  = mujoco.MjData(model)

# Set initial state
data.qpos[0] = np.deg2rad(30)  # 30 degrees
data.qvel[0] = 0.0

# mj_forward: compute derived quantities, no time advance
mujoco.mj_forward(model, data)
print(f"after forward: time={data.time:.3f}")
print(f"  qacc={data.qacc[0]:.4f}")   # computed!

# mj_step: integrate, advance time
mujoco.mj_step(model, data)
print(f"after step:    time={data.time:.3f}")
print(f"  qpos={data.qpos[0]:.4f}")   # changed!
print(f"  qvel={data.qvel[0]:.4f}")   # changed!
