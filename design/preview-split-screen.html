Lesson 01

MJCF Hierarchy

How XML becomes a physics model. Bodies, geoms, joints.

Mental Model

Think of an MJCF file as a family tree. The <worldbody> is the root. Each <body> is a node that can hold geometry (<geom>) for collision and appearance, plus joints (<joint>) that define how it moves relative to its parent. When MuJoCo loads this tree, it compiles it into a flat array structure optimized for simulation.

Look at the pendulum in the simulation pane. The anchor point is the world body. The rod and bob are children, connected by a hinge joint. Drag the sliders to see how changing the hierarchy's parameters reshapes the physical model.

The Nesting Rule

Every <body> lives inside another body or inside <worldbody>. Joints belong to the body they are defined in, and they constrain that body relative to its parent. Geoms give bodies shape, mass, and collision surfaces.

A single body can hold multiple geoms (compound shapes) and multiple joints (combined degrees of freedom). The order matters: MuJoCo processes joints in definition order when computing forward kinematics.

MJCF / XML
<mujoco model="pendulum">
  <worldbody>
    <!-- Anchor: fixed in world frame -->
    <body name="anchor" pos="0 0 2">
      <geom type="sphere" size="0.05"/>

      <!-- Pendulum arm: child of anchor -->
      <body name="arm" pos="0 0 0">
        <joint type="hinge" axis="0 1 0"/>
        <geom type="capsule"
              fromto="0 0 0  0 0 -1"
              size="0.02"/>
        <geom type="sphere"
              pos="0 0 -1" size="0.08"/>
      </body>
    </body>
  </worldbody>
</mujoco>

Compilation: Tree to Arrays

When you call mj_loadXML, the tree is flattened into mjModel. Body 0 is always the world. Each body gets an index, and joint/geom indices follow body order. The body_parentid array preserves the tree structure so the engine can walk it during forward kinematics.

Try adjusting the rod length slider in the simulation. In the compiled model, this changes model.geom_size for the capsule and model.geom_pos for the bob. The hierarchy stays the same; only the numeric parameters change.

Prediction Exercise

Set the angle to about 45 degrees and the rod length to maximum. Before looking at the simulation, predict: will the bob be higher or lower than the anchor point?

Now check the simulation pane. The bob position depends on both the rod length and the angle. At 45 degrees, the vertical drop is length * cos(45) = length * 0.707, so the bob is always below the anchor for angles less than 90 degrees.

Checkpoint
  • You can identify the parent-child relationship in an MJCF body tree
  • You understand that joints connect a body to its parent, not to its children
  • You know that geoms provide shape and mass, not connectivity
  • You can trace how XML nesting maps to body_parentid arrays
Lesson 02

Frames & Axes

Local vs world coordinates. Where things actually are.

Mental Model

Every body in MuJoCo carries its own coordinate frame: an origin and three axes (x, y, z). When a body's pos says "0 0 1", that means 1 unit along the parent's z-axis, not the world's. Frames compose: a child's world position is its local offset transformed through every ancestor's frame, all the way up to worldbody.

The simulation pane shows a two-link arm with visible coordinate frames. The red/green/blue lines at each joint are the local x/y/z axes. Watch how rotating one joint moves the second link's entire frame.

Coordinate Composition

If body A is at position p_A in the world, and body B is defined at local offset p_B_local inside A, then B's world position is:

Math / Pseudocode
# World position of child B
p_B_world = p_A_world + R_A @ p_B_local

# R_A is the 3x3 rotation matrix of body A
# @ is matrix multiplication
# The rotation "re-interprets" the local offset
# in world coordinates

This is why joints matter so much for frames. A hinge joint changes the rotation matrix R of its body. When a parent rotates, all descendants rotate with it, because their world positions depend on the parent's R.

Reading Frames in Code

Python
import mujoco

model = mujoco.MjModel.from_xml_path("arm.xml")
data  = mujoco.MjData(model)

# Set joint angles
data.qpos[0] = 0.5   # base hinge: 0.5 rad
data.qpos[1] = -0.3  # elbow hinge: -0.3 rad

# Compute kinematics (no dynamics)
mujoco.mj_forward(model, data)

# World position of the end effector body
body_id = model.body("end_effector").id
world_pos = data.xpos[body_id]
print(f"End effector at: {world_pos}")

In the simulation, adjust the hinge angle slider. Notice how the second link's frame (shown at its base) rotates relative to the first link. The world-frame grid stays fixed. This is the core of forward kinematics: joint angles determine body frames, which determine world positions.

Prediction Exercise

Set the base height to maximum and the link offset to about halfway. Now move the hinge angle. Does the tip of the second link trace a circle or an arc?

It traces a perfect circle. The hinge constrains motion to rotation around a single axis. The radius of that circle equals the link offset distance. The center of the circle is at the hinge location in world coordinates.

Checkpoint
  • You can distinguish local-frame coordinates from world-frame coordinates
  • You understand that data.xpos gives world positions after mj_forward
  • You know that rotating a parent rotates all of its descendants
  • You can predict how changing a joint angle affects downstream body positions
Lesson 03

State & Stepping

mj_forward vs mj_step. How simulation advances.

Mental Model

The simulation state lives in mjData. The two most important arrays are qpos (generalized positions) and qvel (generalized velocities). Together, they fully describe the mechanical state of every joint in the system.

mj_forward computes everything (positions, velocities, forces) from the current state without advancing time. It answers: "Given this state, what does the world look like?"

mj_step does everything mj_forward does, then integrates forward by one timestep. It answers: "Given this state, what happens next?" Look at the sandbox in the simulation pane. Setting angle and velocity, then pressing Step, shows exactly one timestep of physics.

The State Vector

For a single hinge joint, qpos has one entry (the angle in radians) and qvel has one entry (angular velocity in rad/s). For a free-floating body, qpos has 7 entries (3 position + 4 quaternion) and qvel has 6 (3 linear + 3 angular). The sizes differ because quaternions have 4 components but only 3 degrees of freedom.

Python
import mujoco

model = mujoco.MjModel.from_xml_path("pendulum.xml")
data  = mujoco.MjData(model)

# Set initial state
data.qpos[0] = 1.0   # angle: 1 radian
data.qvel[0] = 0.0   # velocity: at rest

# Compute derived quantities (no time advance)
mujoco.mj_forward(model, data)
print("Before step:", data.qpos[0])

# Advance one timestep (default 0.002s)
mujoco.mj_step(model, data)
print("After step: ", data.qpos[0])
print("Velocity:   ", data.qvel[0])

Forward vs Step

A common mistake: calling mj_forward in a loop and wondering why nothing moves. mj_forward is a pure function of state. It never modifies qpos or qvel. Only mj_step integrates the equations of motion and updates the state.

Use the simulation pane to test this. Set an angle and velocity, then press Step. The angle changes based on the velocity. Press Step again and observe how gravity causes the velocity to change, which then changes the angle by a different amount. Press Reset to restore your initial values and try again.

Python
# Simulate 1 second at default timestep
n_steps = int(1.0 / model.opt.timestep)

for i in range(n_steps):
    mujoco.mj_step(model, data)

# After 500 steps of 0.002s each:
# data.time == 1.0
# data.qpos and data.qvel reflect
# the accumulated physics
Prediction Exercise

In the sandbox, set the angle to 0 (straight down) and velocity to 0. Press Step several times. What happens?

Nothing changes. At angle 0 with zero velocity, the pendulum hangs at equilibrium. Gravity pulls straight down along the rod, producing zero torque. The state remains constant. Now set a small velocity and step: the angle changes because velocity is nonzero, and gravity gradually slows or accelerates the motion.

Checkpoint
  • You understand that qpos and qvel together define the full state
  • You know mj_forward computes derived quantities without advancing time
  • You know mj_step integrates forward by one timestep
  • You can predict how gravity affects a pendulum's velocity over successive steps
