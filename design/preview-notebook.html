Lesson 01

MJCF Hierarchy

How XML becomes a physics model. Bodies contain geoms for shape and joints for motion. Everything nests inside a single world body.

Mental Model

A tree of bodies, not a bag of shapes

An MJCF file describes a kinematic tree. The <worldbody> is the root. Each <body> inside it defines a rigid link. Geoms give that body a shape and collision surface. Joints define how the body moves relative to its parent.

The key insight: child bodies inherit their parent's coordinate frame. When you rotate the shoulder, the elbow and hand move with it. That is not because of code; it is the tree structure doing the work.

import mujoco

MJCF = """
<mujoco>
  <worldbody>
    <body name="mount" pos="0 0 1.5">
      <body name="rod" pos="0 0 -0.5">
        <joint name="hinge" type="hinge" axis="0 1 0"/>
        <geom type="capsule" size="0.02 0.5"/>
        <body name="bob" pos="0 0 -0.5">
          <geom type="sphere" size="0.08" mass="1.0"/>
        </body>
      </body>
    </body>
  </worldbody>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(MJCF)
data  = mujoco.MjData(model)

# Set the hinge to 30 degrees
data.qpos[0] = 0.5236  # radians
mujoco.mj_forward(model, data)

print("bob position:", data.xpos[2])

Lesson 02

Frames & Axes

Local versus world coordinates. Every body carries its own frame. Transformations chain from parent to child through the tree.

Mental Model

Stacking coordinate frames

In MuJoCo, when you write pos="0 0 -0.5" inside a child body, that offset is in the parent's local frame. The simulator chains all these local transforms to compute the world position you see in data.xpos.

Think of it like giving directions: "go 3 blocks north, then 2 blocks east" works because each instruction uses the current heading. The world position is the sum of all those relative moves, rotated by all the joints along the way.

This lesson's widget lets you see both frames at once. The colored axes are the local frame; the dotted axes are the world frame. Watch how they diverge as you change the hinge angle.

frames.py Python 
import mujoco
import numpy as np

MJCF = """
<mujoco>
  <worldbody>
    <body name="base" pos="0 0 0.8">
      <geom type="box" size="0.1 0.1 0.4"/>
      <body name="link" pos="0 0 0.8">
        <joint name="hinge" type="hinge" axis="0 1 0"/>
        <geom type="capsule" size="0.03 0.4"/>
      </body>
    </body>
  </worldbody>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(MJCF)
data  = mujoco.MjData(model)

# Rotate hinge 45 degrees
data.qpos[0] = np.radians(45)
mujoco.mj_forward(model, data)

# data.xpos gives world coordinates
print("link world pos:", data.xpos[2])
# data.xmat gives the 3x3 rotation matrix
print("link frame:", data.xmat[2].reshape(3,3))

At hinge_angle = 90, where does the local x-axis point in world coordinates?

The local x-axis starts pointing to the right (world +x). The hinge rotates around the y-axis. Think about what a 90-degree rotation around y does to the x-axis.

At hinge_angle = 90, local x_axis in world coords = (____, ____, ____)
A 90-degree rotation around the y-axis maps +x to -z in world coordinates. So local x_axis = (0, 0, -1) in world frame. Set the slider to 90 and watch the red arrow: it points straight down, which is the -z direction. The blue z_local arrow points to the right, which is +x in world.

Lesson 03

State & Stepping

What mj_forward and mj_step actually compute. The state vector holds position, velocity, and acceleration. Stepping integrates forward in time.

Mental Model

Two functions, two purposes

mj_forward(model, data) takes the current qpos and qvel and computes everything that depends on them: body positions, contact forces, sensor readings, accelerations. It does not advance time. Use it when you set a state and want to see the consequences.

mj_step(model, data) does everything mj_forward does, then integrates the equations of motion to advance qpos and qvel by one timestep. It also increments data.time.

The state of a MuJoCo simulation is fully captured by (time, qpos, qvel, act). Everything else is derived. That means you can save and restore states by copying just those four arrays.

stepping.py Python 
import mujoco

model = mujoco.MjModel.from_xml_string(MJCF)
data  = mujoco.MjData(model)

# Set initial state
data.qpos[0] = 0.7854   # 45 degrees
data.qvel[0] = 0.0

# Compute derived quantities (no time advance)
mujoco.mj_forward(model, data)
print("qacc after forward:", data.qacc[0])

# Step the simulation 100 times
for i in range(100):
    mujoco.mj_step(model, data)

print("time:", data.time)
print("qpos:", data.qpos[0])
print("qvel:", data.qvel[0])
Prediction Exercise

After mj_forward with angle=45, what sign is qacc?

Gravity pulls the bob down. At 45 degrees, the pendulum is displaced to one side. Think about which direction gravity's torque wants to rotate the hinge.

qacc after mj_forward at 45 deg is (positive / negative / zero): ____
Negative. Gravity creates a restoring torque that accelerates the pendulum back toward the hanging position (angle = 0). At positive angles, the angular acceleration is negative. Click "Step 1x" a few times and watch qvel go negative, confirming the pendulum swings back toward center.
